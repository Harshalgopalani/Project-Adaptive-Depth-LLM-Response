## 1. Executive Summary & Business Rationale

### 1.1 Problem Statement
Enterprise usage of conversational Generative AI tools is scaling rapidly across internal workflows and customer-facing software. However, current LLM deployments incur two primary business penalties:
1. **Productivity Penalty (Cognitive Fatigue):** Employees waste significant working memory reading unstructured 500-word responses to retrieve basic facts or brief code snippets. This inflates **Read-Time-to-Action (RTTA)** and lowers daily task throughput.
2. **Financial Penalty (Token Infrastructure Costs):** Output tokens generated by commercial LLMs carry a high cost multiplier relative to input tokens. Generating hundreds of redundant filler words per request consumes excessive cloud/API compute budgets.

### 1.2 Business Objective
Project Adaptive Depth establishes a **Dynamic Contextual Depth (DCD)** framework that intelligently matches output verbosity to user task complexity. 

* **Primary Financial Goal:** Lower enterprise LLM inference API expenditure by **15–22%** per session.
* **Primary Operational Goal:** Accelerate user information extraction speed (RTTA) by **40%**.
* **Strategic Position:** Provide an intuitive GenUI experience that dynamically handles response depth without requiring users to manually write complex prompts like *"be concise"*.

## 2. Business Scope

### In-Scope
* Development and fine-tuning of an open-source Small Language Model (SLM) router deployed on ultra-low-latency LPU infrastructure.
* Implementation of Task Complexity Indexing (TCI 1–5) logic to categorize prompts in real time.
* JSON schema enforcement and system-prompt parameter capping for low-complexity prompts.
* Design and engineering of a progressive disclosure frontend interface (Executive Anchors, Accordions, and Depth Sliders).
* Automated fallbacks for schema errors, router timeouts, and safety edge cases.

### Out-of-Scope
* Training foundational base LLMs from scratch.
* Modifications to core RAG vector indexing or database storage pipelines.
* Fine-tuning primary heavy models (Claude/GPT) for general reasoning capability.

## 4. Enterprise Process Modeling (Dual-State)

### 4.1 "As-Is" Workflow (Manual / Standard Streaming)
1. User enters a prompt into the text chat console.
2. Prompt is sent directly to the Heavy LLM API endpoint.
3. Heavy LLM processes query with standard system instructions and generates an unconstrained stream of text.
4. Interface renders a uniform 500+ word "wall of text" containing preambles, main content, and disclaimers.
5. User manually reads and skims the output to locate key facts or code (High Cognitive Friction; High Token Cost).

### 4.2 "To-Be" Workflow (Dynamic Contextual Depth)
1. User enters a prompt into the text chat console.
2. Ingress layer scrubs PII and forwards prompt to the ultra-fast SLM Router.
3. SLM Router evaluates task complexity (TCI score) in $< 50\text{ ms}$.
4. **Path A (TCI $\le$ 2 - Low Complexity):** Inject JSON schema constraint and set `max_tokens = 150`. Heavy LLM outputs structured JSON.
5. **Path B (TCI $\ge$ 3 - High Complexity):** Bypass constraints. Heavy LLM outputs full markdown reasoning stream.
6. GenUI frontend parses response and renders Executive Anchor callout, collapsible detail modules, and context depth controls.
7. User accesses immediate facts instantly or expands accordions for deeper context (Low Cognitive Friction; Optimized Token Cost).

## 6. Business ROI & Cost-Benefit Modeling

### 6.1 Baseline Cost Model (Standard Unconstrained Generation)
* Monthly Query Volume: $1,000,000$ queries
* Average Output Tokens / Query: $800\text{ tokens}$
* Commercial LLM Output Token Rate: $\$0.000015\text{ per token}$ ($\$15.00\text{ per million tokens}$)
* **Total Monthly Output Token Expense:** $1,000,000 \times 800 \times 0.000015 = \mathbf{\$12,000.00 / \text{month}}$

### 6.2 Projected Cost Model (With DCD Architecture)
* Query Breakdown:
  * **Low Complexity Queries (70%):** $700,000\text{ queries}$ capped at average $180\text{ output tokens}$.
  * **High Complexity Queries (30%):** $300,000\text{ queries}$ unconstrained at average $800\text{ output tokens}$.
* Output Token Costs:
  * Low Complexity: $700,000 \times 180 \times 0.000015 = \$1,890.00$
  * High Complexity: $300,000 \times 800 \times 0.000015 = \$3,600.00$
* SLM Router Operating Expense (Groq LPU API): $1,000,000 \times \$0.0000005 = \$500.00$
* **Total Projected Monthly Expense:** $\$1,890 + \$3,600 + \$500 = \mathbf{\$5,990.00 / \text{month}}$

### 6.3 Net ROI & Business Value
* **Direct Monthly Net Savings:** $\$12,000 - \$5,990 = \mathbf{\$6,010.00 / \text{month}}$ (**$50.08\%$ reduction in token-related compute overhead**).
* **Productivity Gains:** Reduced average time spent per informational lookup from 35 seconds to 8 seconds across enterprise users.
